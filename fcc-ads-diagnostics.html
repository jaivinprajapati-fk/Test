FCC Ads Serving Diagnostics

Action Plan
Objective: Monitor end-to-end: from searches on Nahdi's website to ad serving. Identify where requests break down and why ads are or aren't served.

Phase 1: Request Flow Health (Last 30 Days)

Why this matters: Structural breaks in the pipeline (requests not sent, not received, or no response) block everything downstream.
Stage What We're Measuring
Sent % of Nahdi searches that trigger an ad bid request to FCC
Received % of sent requests that are logged/received by FCC Ad Server
Response Breakdown of Ad Server responses: (1) Ad returned, (2) No ad, (3) Invalid request, (4) No response, (5) Other error
Deliverable from tech: Raw counts for each stage + response breakdown %.

Phase 2: Keyword-Campaign Matching vs. Actual Ad Serving

Why this matters: Keyword match is necessary but not sufficient for serving. We need to validate against actual behavior.
Setup: For each search query, determine: Does an active campaign keyword match it?
  • Exact match: Query = keyword
  • Phrase match: Query contains all keyword words (any order); query can have extra words
Compare this against: Did an ad actually get served?
Keyword Match? Ad Served? Count Investigation
Yes Yes N Verify serving was correct (bid × relevance × user ranking logic)
Yes No N First priority. Why didn't ad serve despite keyword match? (See breakdown below)

Deliverable from tech: Count for each cell + qualitative findings for each.

Phase 2B: Deep Dive — Keyword Matched, Ad NOT Served

Why we're doing this: Keyword match alone isn't enough. Ads can fail to serve due to filters, system issues, or data problems.
Possible failure buckets:
1. Request-level filters — get_bid API filters (e.g., brand filters in user request, category filters applied)
2. Brand/Category mismatch — Product's brand/category doesn't align with query context
3. Category classifier error — Query categorized wrong; ad group for correct category filtered out
4. Solr retrieval gap — Product in campaign but not in Solr pool, or Solr didn't return it
5. Query normalization issue — Case sensitivity, language detection mismatch, spell correction altered query
6. Language/transliteration mismatch — Query language doesn't match keyword language
7. Other — Auction ranking loss (bid/relevance/user factors), or other system issue
Deliverable from tech: For all queries in Row 2, bucket them by failure reason above. Count per bucket.
