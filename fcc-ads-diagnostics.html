Keyword match is necessary but not sufficient for serving. We validate expected behavior against what actually happened.

  • Phrase match: Query contains all keyword words (any order); query can have extra words

Deep Dive — Keyword Matched, Ad NOT Served

Why we're doing this: Keyword match alone isn't enough. Ads can fail to serve due to filters, system issues, or data problems.
Possible failure buckets:
1. Request-level filters — get_bid API filters (brand filters in user request, category filters applied)
2. Brand/Category mismatch — Product's brand/category doesn't align with query context
3. Category classifier error — Query categorized wrong; ad group for correct category filtered out
4. Solr retrieval gap — Product in campaign but not in Solr pool, or Solr didn't return it
5. Query normalization issue — Case sensitivity, language detection mismatch, spell correction altered query
6. Language/transliteration mismatch — Query language doesn't match keyword language
7. Auction ranking loss — Ad matched and retrieved but lost in bid × relevance × user ranking
Outcome we're looking at: For all queries where keyword matched but no ad served, bucket them by failure reason. Count per bucket. This pinpoints the exact step where the chain breaks.

What This Analysis Reveals

  • Keyword Matching vs. Serving — Does the system behave as expected when a campaign keyword exists?
  • Root Cause Buckets — For every failure, we know exactly where it broke: filters, retrieval, ranking, data, or system issue
