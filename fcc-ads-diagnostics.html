Serving Accuracy: Matching vs. Reality

Once we know the pipeline carries requests end-to-end, we check if the system responds correctly. For every search query, we look back at that moment in time and ask: Did any active campaigns have keywords that should match this query? Then we compare that to what actually happened.
How We Check: For each search event, snapshot the campaigns that were active at that exact moment. Then test: does the query match any of those campaigns' keywords using our match rules?
  • Exact match: Query text = keyword text
  • Phrase match: Query contains all words from the keyword (order doesn't matter); query can have additional words
Next, check the system's actual response. Compare expected (keyword matched) to actual (ad served or not).

Root Cause Breakdown — When Keywords Match But Ads Don't Serve

For every query where a campaign keyword should match but no ad was served, we isolate the exact reason. Each bucket is a root cause, not a symptom. Each has a count so we know what to fix first.
Failure Buckets (in priority order by impact):
1. Client catalogue sync issue — Products in the campaign exist in the client's catalogue but were never synced to our system, or sync is stale. We can't serve what we don't know about.
2. Query parsing broke the keyword — Spell correction, language detection, case normalization, or transliteration altered the query so it no longer matches the keyword in our index.
3. Category classification filtered out the ad group — Query was assigned the wrong category. The correct category ad groups were excluded before retrieval.
4. Solr retrieval returned nothing — Keyword matching rules passed, category passed, but Solr (product or banner group pool) returned zero results for this query.
5. Auction ranking loss — Ad was retrieved and eligible, but lost in the final ranking due to bid amount, relevance score, or user-level signals.
6. User-requested filters excluded it — User applied filters in the search (brand, price range, etc.) that eliminated all matching ads.
What We Get: Each bucket gets a count of affected queries. Each count tells us the magnitude of the problem and what to tackle first. Each bucket is concrete (a root cause we can fix), not vague.

What This Analysis Reveals

  • Keyword Matching vs. Serving — Does the system behave as expected when a campaign keyword exists?
  • Root Cause Buckets — For every failure, we know exactly where it broke: filters, retrieval, ranking, data, or system issue
