FCC Ads — Serving Eval Framework
Sep 2026 · Scope: Ad serving only — campaign setup, attribution, and reporting are out of scope of this document.
North Star
What Are We Measuring?
The end objective of the ads engine is: a user searches → a relevant ad is served → user clicks → user converts. Every eval metric traces back to this chain. We don't start by measuring individual components — we start by measuring the outcome and drill into components only when the outcome shows a gap.
ROAS = Revenue attributed to ad clicks / Ad spend
Return on Ad Spend — the single number that captures advertiser value. A drop means either we're not serving enough, serving irrelevant ads, or clicks aren't converting.
Why ROAS and not Ad Click Rate: A click is a necessary but insufficient signal. An ad can generate high CTR and zero conversions — the click-bait failure mode. ROAS closes this loop: if a campaign generates clicks but no purchases, ROAS drops and the problem surfaces. We charge CPC, but the advertiser's goal is the order — ROAS is the metric that aligns our measurement with their actual objective.
Incrementality caveat: ROAS as measured here is attributed ROAS — revenue from orders placed after an ad click. We cannot currently determine if those buyers would have converted without the ad (incrementality), as that requires organic conversion data and holdout experiments. This is a known limitation to revisit as measurement matures.
Decomposition
When ROAS Shows a Gap — Where to Look
ROAS breaks into three independent levers. When the number drops, this tells you which problem you have.
ROAS = Serve Rate × CTR × Conversion Rate × AOV / CPC
Serve Rate = ads served / total searches  |  CTR = clicks / ads served  |  Conv. Rate = orders / clicks  |  AOV = avg order value
Serve Rate drops
Engine is missing queries. Relevant campaigns exist but ads aren't reaching users. Fewer impressions means fewer chances to convert.
CTR drops
Serving frequently but wrong ads — users see them and don't act. Relevance problem upstream in the pipeline.
Conv. Rate drops
Clicks are happening but not converting. Landing page, product-query mismatch, or pricing issue. Outside serving scope but tracked here as a guardrail.
Serving scope boundary: Serve Rate and CTR are within the serving engine's control. Conversion Rate and AOV are advertiser-side signals — we track them as ROAS guardrails, not as serving metrics to fix.
Level 2 — Relevance
Was What We Served Relevant?
When CTR is low, it means we're serving ads but users aren't clicking. The goal is to identify which segment of queries is driving the low CTR — not to audit every served ad.
1
Overall CTR — baseline
Track weekly. This is your single relevance health number. Any sustained drop triggers investigation.
↓
2
CTR by query volume tier
Segment queries into head (top 20% by volume), torso, and tail. Head queries drive ~80% of traffic — if CTR is dropping there, it's a systemic problem. If only in tail, it's more contained.
↓
3
CTR by match type
Exact match ads should have higher CTR than phrase match — the query is more specific. If exact match CTR is low, the served product isn't matching the keyword well. If phrase match CTR is low, the matching is too broad.
↓
4
CTR by position
Position 1 should get significantly more clicks than position 2, 3, etc. If CTR across positions is flat — ranking isn't differentiating. The right product isn't being put first.
Important: Low CTR at this stage doesn't tell you which pipeline step caused the wrong ad to be served. It tells you that something upstream is wrong. The segmentation narrows where to look — RCA into the pipeline components follows from there.
Level 3 — False Negatives
Should We Have Served Something But Didn't?
When Serve Rate is low, we need to understand: for the queries where nothing was served, was there a relevant campaign that should have matched? This is the false negative rate — the most operationally important gap to track.
1
Take all no-ad queries from the query log
Every search query that returned no served ad is your starting universe for this analysis.
↓
2
Run keyword matching logic offline against active campaigns
For each no-ad query, check: does an active campaign have a keyword that should match this query (exact or phrase)? This is run offline — not in production — against a snapshot of active campaigns at the time of the query.
↓
3
Bucket the results
Two outcomes:

Keyword should have matched → no ad served — confirmed false negative. The engine had a campaign for this query and failed to serve it. This is a serving failure. Volume of this bucket is your false negative rate.

No keyword matched — either a campaign gap (client hasn't configured this keyword) or a true negative (no relevant product). These require a separate catalogue-level relevance check to distinguish — deferred to a later phase.
↓
4
Track false negative rate weekly
False negative rate = confirmed false negatives / total no-ad queries. This is the number to own. Any upward trend means the serving pipeline is dropping more queries it should be catching.
On "true negatives": Queries where no keyword matched are not assumed to be correct. Distinguishing a campaign gap from a genuine no-match requires a catalogue-level relevance check — this is a known open item, deferred to Phase 2 of this eval framework.
Relevance Reviewer
External Check on Product Relevance
The system's internal relevance score is currently a black box. To measure true relevance independently — and push the system to improve — we run an external reviewer offline on served query-product pairs. It uses only catalogue data (product name, description, category) and the search query. Four approaches, layered by confidence and cost.
What this reviewer does: For a given (query, served product) pair, it answers — is this product genuinely relevant to this query? Independent of what the system internally computed. Over time, gaps between the system's relevance score and this external score pinpoint where the relevance logic needs improvement.
1
Lexical Match — Baseline filter
Check if query terms appear in the product name, description, or category. Fast, zero infrastructure. Use as a floor check — if a served product fails this, it's a clear irrelevance signal with no further review needed.
2
Embedding Similarity — Primary signal
Convert query and product text into vectors using a multilingual model (handles Arabic + English). Compute similarity score. Pairs above threshold = relevant; below threshold = flagged. Use as the main automated relevance signal running on sampled served pairs weekly.
3
LLM-as-Judge — Ambiguous case review
For pairs that score low or borderline on embedding similarity, pass them to an LLM with query + product metadata and ask for a structured relevance rating (1–3) with a one-line reason. Use on the flagged subset from Approach 2 — not on everything.
4
Golden Set + NDCG — Trend metric
A fixed set of ~100 high-traffic queries with human-labelled correct products. Run your system against this weekly. NDCG@5 score tells you whether the right products are coming back in the right order. This is the only metric that shows whether the system is improving or degrading over time.
Output: A weekly irrelevance rate (% of served ads that fail the external check) and a weekly NDCG score on the golden set. Together these give you both a snapshot and a trend line on relevance quality.
Summary
Metrics to Track, In Order
Track these weekly. Each metric only requires investigation when it moves — you don't audit everything all the time.
Metric What It Tells You Triggers Investigation When
ROAS Overall advertiser value — revenue returned per unit of spend Drops week-over-week; then decompose into Serve Rate, CTR, Conv. Rate
Serve Rate How many searches result in an ad being served Drops without a corresponding drop in active campaigns
CTR Whether served ads are relevant enough for users to click Drops — then segment by tier, match type, position
Conversion Rate Whether clicks are resulting in orders (guardrail, not a serving metric) Drops while CTR is stable — signals post-click / product issue
False Negative Rate Queries where a campaign existed but no ad was served Rises — pipeline is dropping queries it should be serving
